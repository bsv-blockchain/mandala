## 7. Contract drift, surprises, UNVERIFIED

1. **§11.1 vs Go reality.** Contract line 120 says Go is "unchanged" re §9.7's in-flight 503 (line 71). No in-flight set exists in `overlay-go/internal` (grep for `flight|concurren|Mutex|lock` → none), and v1.3.7 `Engine.Submit` takes no lock (`engine.go:312`; the only `e.mu` use on the submit path is `validateTopicsAndGetManagers` RLock, :401-403). So Go submits run fully concurrently, and two same-txid submits can both pass `serveKnownVerdict` (`submit.go:145-149`) before either writes. Whether some other mechanism makes §9.7 hold in Go: UNVERIFIED (likely stale contract text). Relevant to the gate design: Go's shared slot overlaps real concurrency, TS's does not.
2. **§11.9 vs TS P2.** Contract line 128 specifies `restore.tokenRows` with a keyed union; TS P2 dropped `tokenRows` ("A legacy stored `tokenRows` is dropped (clean break)", `submitSideChannel.ts:47-48`) and restores from `mandalaOwners`. Go still writes and replays `TokenRows` (`admissions.go:34`, `wiring/engine.go:355-362,600-609`). P3 must choose: port the journal restore and drop `tokenRows`, or keep legacy rows; the contract text needs a v3 update either way.
3. **Balance on eviction.** Go `OutputEvicted` deletes the token row with "No balance adjustment" (`lookup_service.go:280-292`); v3 package `outputEvicted` debits the owner (`MandalaLookupService.d.ts:59-61`), and TS adds `retireOutputs` to re-run it after the engine swallows a failure (`eviction.ts:144-160`).
4. **Envelope decode placement.** Go rejects a malformed off-chain payload in httpapi as unpersisted 400 ERR_SHAPE (`submit.go:119-121`); TS lets the package manager reject it as a typed ERR_SHAPE, which TS persists per payload hash (`types.d.ts:122-123`, `submitVerdict.ts:87-89`).
5. **Untyped rejects.** TS answers untyped manager throws ERR_SHAPE but never persists them (`admission.ts:494-497`); Go persists every unmatched tm_mandala reason as final ERR_SHAPE (`verdict.go:51,126,159-161`).
